# 平台中的仿真闭环评测

## 从哪里打开

关闭旧工作台窗口后重新启动，点击顶部 **仿真评测 / 实时观测…**。
在独立窗口中选择模型/后端、设置评测参数，点击“开始闭环评测”。
仿真运行于独立进程，双相机和结果通过事件流显示；模型加载与推理不会阻塞界面。
当前模型闭环支持 **完整拾放 pick_place 及其配置变体**。推、拉、擦拭可用专家自检，但尚未提供经验证的模型阶段判定适配，不直接宣称可评测任意新任务。

## 先做平台自检

1. 主窗口选择“完整拾放”，设置场景、物品、坐标/随机范围，等待模拟器就绪。
2. 打开评测窗口，后端选择“专家控制器自检 · 不是模型成绩”。
3. 设置1次、最大400步，点击开始。
4. 在“实时观测”页查看固定相机、腕部相机、状态、阶段与仿真时间；完成后查看逐次结果。
5. 选中结果，点击“回放选中轨迹”。原始RGB和动作实际存储在HDF5中。

专家自检验证的是专家/物理/记录/界面链路，其成功率不属于训练模型。

## 评测本机训练模型

选择“本地模型 · SmolVLA / π₀.₅”：

评测原始拾放模型时，首次先在主窗口选择“原基础场景”和红色方块，再使用与训练相同的起点/目标范围。切换背景、目标范围或对象应作为单独测试组记录。

- 模型目录：选择包含 config.json、model.safetensors、policy_preprocessor.json、policy_postprocessor.json 和处理器统计文件/分词器的 pretrained_model 目录。
- 推理Python：选择安装了 LeRobot 0.6.2 和该模型依赖的 Python。本机默认 .venv-lerobot；它与MuJoCo采集环境分开。
- 迁移到新电脑时，数据转换环境的dataset依赖不一定包含模型依赖；需准备对应SmolVLA/π₀.₅推理环境及本地基础模型配置/分词器。当前服务离线加载，不会自动下载基础模型。本机models/smolvlm已有必要配置，但它不包含在平台分发包中。
- 设备：CPU可用于连通性检查；CUDA需要对应GPU、驱动及CUDA版PyTorch环境。
- 试验数：先设1。最大400步对应最多20秒仿真时间，但墙钟时间可能远大于20秒。
- 动作前缀：默认每次推理返回动作块后执行前10步，再用最新图像/状态重新推理。默认模型动作块50步。
- 请求超时和加载超时：分别限制每次响应与模型准备时间。CPU较慢时需适当增加。

输入固定为7维状态、overview→camera1、wrist→camera2两路320×240 RGB，以及任务文本。
图像先转RGB CHW float32 [0,1]，随后使用checkpoint原有预处理器和后处理器；不会重新计算评测集统计量。
动作固定为6个关节绝对目标rad，加夹爪总开度m；关节顺序沿用平台joint1～joint6。
模型必须按该协议训练，形状相同不代表单位和语义天然相同。
保存实际模型配置、预处理器、后处理器、设备、权重SHA256和精度。SmolVLA已做真实权重推理测试；π₀.₅仅共用加载/服务接口，未完成本机资源与闭环验证。

## 连接4090 / A100推理服务

可在训练工作站使用该机器的模型环境运行最新的：

```bash
python a100/inference_service.py --checkpoint /path/to/pretrained_model --device cuda --port 8765
```

服务默认只监听工作站本机。可通过SSH隧道连接，例如在采集电脑运行：

```powershell
ssh -L 8765:127.0.0.1:8765 用户名@训练工作站
```

平台后端选择“HTTP推理服务”，地址填 http://127.0.0.1:8765 。
若明确需要可信局域网直连，服务可加 --host 0.0.0.0；平台填写工作站IP。此轻量服务没有鉴权，不适合直接开放到公网。
服务单客户端；同一个实例不要同时给多个评测会话使用。
π₀.₅需在对应GPU环境完成可行性检查并确保7维动作和相机映射兼容，不能将服务能启动视为任务执行有效。

## 条件、判据与统计

“从采集主窗口更新”复制当前任务、场景、物品、固定位置/随机范围。
开始前固定全部试验的物体/目标坐标、场景seed和策略噪声seed，保存 frozen_protocol.json。评测中不会用专家可达性预检筛掉模型失败条件。
默认条件组标签 custom_unclassified：平台不会自动把这些条件宣称为训练已见/留出或泛化测试。
两种模型应使用同一份固定清单；记录各自预处理差异。示例清单：

```json
{"conditions":[
  {"seed":130001,"policy_noise_seed":101,"start_xy":[0.40,-0.10],"goal_xy":[0.34,0.18]},
  {"seed":130002,"policy_noise_seed":202,"start_xy":[0.39,-0.08],"goal_xy":[0.37,0.12]}
]}
```

选择该JSON时，试验数必须等于清单条数。清单记录具体坐标，便于跨模型复现。
完整拾放沿用原来的稳定持有、未丢物、稳定释放承载和连续交接判据；阶段由状态证据标注，仅用于评测/终止，不输入模型，也不用专家替模型生成动作。
目标检查使用本次实际目标坐标，而非固定绿色区域位置。
这里不把 grasp/place 阶段自动升级为可靠独立技能，也没有真机控制接口。

报告包括每次成功/失败/中断、终止原因、仿真与墙钟任务时间、模型推理和端到端请求的p50/p95、原始耗时样本、超时、空队列、人工停止及动作越界数。
分位数按所有实际请求样本统计，包含首次请求；模型加载时间不算每条任务时间。首次请求可能受冷启动影响。
动作块越界/非有限值时整块拒绝，不进行裁剪。停止时清空队列；停止后的在途响应不得执行。
推理超时会终止本批，避免仍在途的响应影响下一条。
人工中断单独报告，不进入已完成试验成功率分母；界面同时显示计划数、已完成数。
首次应先固定成功判据和验收门槛。自定义试跑报告不是自动满足历史完整验收协议。

## 实时观测与实时控制的区别

当前采用同步闭环：请求推理时暂停物理仿真，推理完成后按20Hz动作步长继续执行。
界面在等待时显示等待秒数，可操作停止。选择“按20Hz播放动作”便于人观察，关闭则尽快推进仿真。
这些指标不能证明硬件实时调度、网络抖动或异步动作队列的时限性能；报告明确 real_time_deadline_validation=false。
例如本机CPU单次动作块推理实测约27.5秒，该数值只是一次测量，不是4090/A100的推理性能。

## 保存位置与停止

所有结果位于 data/evaluations/run_时间/（随PIPER_WORKBENCH_DATA迁移）：

- config.json、effective_config.json、frozen_protocol.json：请求设置、实际设置、固定条件与代码哈希。
- model_description.json、model_service.log：模型/处理器/设备/精度及加载诊断；HTTP使用服务器实际描述。
- trials.jsonl、summary.json：逐次与汇总指标，可在“打开历史评测目录”中读取。
- raw/*.h5：评测专用图像、状态、实际执行动作、阶段和物理证据；不会自动进入采集训练集。
- runner.log、error.log：运行和错误记录。

“停止并清队列”请求安全结束，等待在途调用返回后保存当前记录；等待期间不推进动作。
“强制终止本次进程”结束该次评测进程树，已完成报告保留，未提交轨迹可能留下partial HDF5，不能当作有效完整轨迹。
关闭工作台前应结束评测。模型加载失败、缺GPU依赖或超时都会在界面及日志中显示，不产生虚构模型成绩。
